# 从用户数据生成评估报告

> 编号 `REQ-WL-PLAN-06` ｜ 项目：科学减重（WL）｜ 模块：方案·评估·随访 ｜ 优先级 P0 ｜ 状态：待评审
> Demo：[评估报告（14 位样例患者，顶栏 ⋯ 切换）](https://lipulin222.github.io/health-subscription-demo/weight-management/Assessment-report/index.html)

---

## 1. 规则

### 1.1 数据传入

系统把用户数据加工成诊断字段，按提示词「输入」一节定义的 A–G 七组传入 AI（用户消息传 JSON）。

字段的最终加工口径（由哪侧产出、以什么格式传入）——待技术确认。

### 1.2 生成提示词

生成报告用的提示词为**内部文档，不随本单公开**。其内容涵盖：A–G 七组输入字段定义、三档分档、结论头与整体建议固定结构、用药模块结构、文案规则与输出格式；整体作为 system 提示词传给 AI，用户消息传加工后的字段 JSON。接入时以内部下发的提示词为准。

### 1.3 页面渲染

- 按提示词「输出格式」渲染：档案行 → 三档刻度 → 解读 → 各模块 → 固定声明。
- 吸底按钮与分流沿用现有评估报告页规则，本单不新增。

## 2. 验收

- [ ] 同一份输入重复生成，分档结果稳定一致
- [ ] 用户端报告不出现体检指标具体数值，只有「血脂偏高」这类定性描述
- [ ] 报告不出现「体重记录只有一次」「作为基线」等体重数据量相关表述
- [ ] 模块标题只用固定五个：整体建议、饮食建议、运动建议、用药建议、就诊建议
- [ ] 整体建议为固定四层结构：阶段描述段为固定原文；结论段用固定句式，阶段短语带高亮标记；特殊提示条目全部来自用户数据，无编造内容；无「体重对健康的影响分为几个阶段」引入句
- [ ] 第 3 档结论段用「已进入慢性疾病阶段」变体，任务落到面诊
- [ ] 第 2 档用药模块以「核心理由是：」开头的人设化理由（另起一行、带高亮标记），理由结合用户自身处境而非通用套话；预期表引语单独另起一行、数值区间与提示词一致；无「会依赖吗」等常见顾虑 FAQ
- [ ] 孕产期用户报告无用药模块
- [ ] 高亮标记全文只出现在阶段短语和核心理由两处
- [ ] 全文无「诊断」「处方」字样，结尾声明原文与提示词一致
