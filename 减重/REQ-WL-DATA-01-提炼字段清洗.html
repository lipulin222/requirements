提炼字段清洗（AI 诊断数据集）

需求单 · 科学减重（WL） · 交付目标：可上线面向用户使用（H5 + 微信小程序）

编号 REQ-WL-DATA-01 ｜ 项目：科学减重（WL）｜ 模块：数据清洗 ｜ 状态：制定中 一句话：把 5 张业务表和企业微信沟通记录合并成「每人一份、按 10 个数据域组织」的提炼数据集（所有明细带时间戳与来源），供医生端「患者身体状况 AI 总结」等场景使用。效果可看 医生速览页。 本单只涉及数据维度与报表设计，不涉及分流等产品逻辑——档位判定等规则由对应需求单另行约定。

1. 做什么

系统里关于一个患者的信息分散在 5 张业务表和企业微信沟通记录里，很多内容重复记录、有的是自由文本，不能直接拿来用。本需求要求把这些数据洗成 每个就诊人一份、按 10 个数据域组织 的数据集。

输入数据（5 张表 + 企微记录）

表 关键内容
就诊人基本信息 姓名、性别、出生日期
订单 订单号、商品名、类别、规格、创建时间
就诊记录 到达时间、接诊医生、身高、体重、病历内容（医生写的自由文本）
体检报告 身高体重 BMI、血压、脉搏、腰围、家族史、既往病史、主要发现、体检建议、创建时间
问卷（记录 + 答案，同一张表） 提交时间、填写渠道、初筛结果、10 道题的逐题回答
企业微信沟通记录 患者与顾问 / 医生的聊天内容、消息时间（感受反馈与副作用线索的来源）

输出的 9 个数据域

数据域 内容
基础信息 就诊人 ID、姓名、性别、年龄（现算）、出生日期
消费记录 订单编号、下单时间、商品内容（商品名）、类别、规格、价格、药程
就诊记录 就诊时间、来源（线上 / 线下）、接诊医生、病历内容原文
用药信息 药品名称、当前剂量、剂量调整记录（从多少调到多少、决策医生；从病历与订单里提取，每条带来源，来源含线上）
副作用情况 用药过程中出现的不适 / 副作用描述（从病历与企业微信聊天记录提取，每条带时间与来源）
基础指标 身高、体重、心率、腰围的全部测量明细（数值 + 测量时间 + 来源），体重另带新鲜度
检验记录 血压、血糖、血脂等检验 / 体检发现（数值或描述 + 参考范围 + 是否异常 + 检验时间 + 来源），指标清单见 2.3
检查记录 B 超、CT 等影像与器械检查（项目、部位、所见结论、是否异常、检查时间、来源），辅助判断
安全筛查 禁忌症（有 / 无 / 不确定 + 命中项）、孕产阶段、年龄（是否满 18 由消费方按出生日期判定）
心态相关 减重目标、原因自评、治疗目标（除体重数字外的目标）、感受反馈（从企业微信聊天记录提取）

2. 输出数据表结构设计

输出为每就诊人一条主记录，主记录下按数据域组织（JSON 或关系表均可，开发照此建表 / 定接口）。所有明细条目带时间戳 recorded_at 和来源 source（约定见 2.2）。

2.1 各数据域字段定义

基础信息 patient_info（单对象）

字段 类型 必填 说明
patient_id 文本 必填 就诊人 ID，主键，来自就诊人基本信息表
name 文本 必填 姓名
gender 枚举：M / F 必填 只取就诊人表（第 3 节）
birth_date 日期 必填 出生日期
age 数值（1 位小数） 必填 按出生日期现算，精确到 0.1 岁；问卷自填年龄只做对账，对不上在输出附注里提示

消费记录 orders（数组）

字段 类型 说明
order_id 文本 订单号
recorded_at 日期时间 下单时间
product_name 文本 商品内容（商品名原文）
category 文本 类别
spec 文本 规格
price 数值（2 位小数） 价格（实付金额，单位元）
treatment_duration 文本 药程：患者使用减重药物的持续时间（如「24 周」），来自订单 / DMS 处方信息

就诊记录 visits（数组）

字段 类型 说明
recorded_at 日期时间 就诊到达时间
doctor_name 文本 接诊医生
source 枚举：线上 / 线下 就诊来源
record_text 文本 病历内容原文（仅医生端可见，见第 7 节红线）

用药信息 medications（数组）

字段 类型 说明
drug_name 文本 药品名称（从病历文本与订单商品名提取）
current_dosage 文本 当前剂量 / 用法，写不出的标「未记录」
recorded_at 日期时间 提取依据那条病历 / 订单的时间
source 枚举：visit 病历（线下就诊）/ order 订单 / online 线上 来源

剂量调整记录 dose_adjustments（数组，挂在用药信息下）

字段 类型 说明
from_dosage 文本 调整前剂量
to_dosage 文本 调整后剂量
doctor_name 文本 做出调整决策的医生
recorded_at 日期时间 决策 / 记录时间
source 枚举：visit 病历（线下就诊）/ online 线上 来源

副作用情况 side_effects（数组）

字段 类型 说明
item 文本 副作用 / 不适描述（如「恶心，饭后明显」「注射部位红肿」），提到具体药物的一并注明
recorded_at 日期时间 病历记录时间或企微消息时间
source 枚举：visit 病历 / wecom 企业微信聊天记录 来源
  • 从病历文本和企业微信聊天记录中提取患者描述的不适与副作用；顾问 / 医生回复的安抚内容不算副作用，不提取；同一不适多次反馈逐条保留，不合并。

基础指标 body_metrics（数组）

字段 类型 说明
metric 枚举：身高 / 体重 / 心率 / 腰围 指标名
value 数值（1 位小数） 测量值，原样输出不换算
unit 枚举：cm / kg / 次 / 分 单位
recorded_at 日期时间 测量时间（无时刻的只落日期）
source 枚举：visit 就诊记录 / exam 体检报告 / questionnaire 问卷自填 来源
  • 同一指标多条全部保留，按时间升序；同一天多条不合并。
  • 空值测量（测了没记数值）不入明细。

检验记录 lab_results（数组）

字段 类型 说明
item 文本 指标名（清单见 2.3，清单外有数据也输出）
value 文本 / 数值 数值或描述（如「轻度脂肪肝」）
unit 文本 单位，描述类为空
reference_range 文本 参考范围，报告有就带
abnormal 枚举：是 / 否 是否偏高 / 异常；「未见异常」类描述不输出
recorded_at 日期 检验 / 报告时间
source 枚举：院内检查 / 院内体检 / 院外体检 / 小程序记录 / 用户自述 / 其他 数据来源

检查记录 exams（数组）

字段 类型 说明
exam_name 文本 检查项目（如「腹部 B 超」「胸部 CT」）
body_part 文本 检查部位
finding 文本 所见 / 结论（如「轻度脂肪肝」）
abnormal 枚举：是 / 否 / 未标注 是否异常
recorded_at 日期 检查 / 报告时间
source 枚举：院内检查 / 院内体检 / 院外体检 / 小程序记录 / 用户自述 / 其他 数据来源
  • 覆盖 B 超、CT、MRI、X 光、内镜、骨密度等影像与器械检查，辅助判断；「未见异常」类描述不输出。
  • 与检验记录的区分：抽血化验、生理测量类进检验记录；影像与器械检查类进检查记录。

安全筛查 safety_screening（单对象）

字段 类型 说明
contraindication 枚举：有 / 无 / 不确定 禁忌症（问卷）
contraindication_items 文本数组 答「有」时的具体命中项
pregnancy_status 枚举：备孕 / 怀孕 / 哺乳 / 无 / 未作答 孕产阶段；男性记「未作答」
recorded_at 日期时间 数据录入时间（不等于问卷提交时间：后台补录、修改后以最近一次录入时间为准）

心态相关 psychology（单对象）

字段 类型 说明
weight_goal 文本 减重目标
gain_causes 文本数组 体重增加原因自评（多选原文）
treatment_goals 文本数组 除体重数字外的治疗目标（问卷第⑩题）
feedback 对象数组 {text, recorded_at} 感受反馈：从企业微信聊天记录里提取的患者主观感受（如「这周不容易饿了」「晚上睡得好了」），每条带消息时间；顾问回复不提取
recorded_at 日期时间 问卷提交时间（feedback 的各条时间在条目内）

2.2 时间戳约定（全字段）

除基础信息（patient_info）外，其余每个数据域的每条明细都必须带时间戳 recorded_at 与来源 source：

数据类别 时间戳取值
消费记录 订单下单时间
就诊记录 就诊到达时间
用药信息 提取依据那条病历 / 订单的时间
副作用情况 病历记录时间或企微消息时间（按来源）
基础指标 该次测量时间
检验记录 检验 / 报告时间
检查记录 检查 / 报告时间
安全筛查 数据录入时间
心态相关 问卷字段用问卷提交时间；感受反馈各条用企微消息时间
  • 时间戳原样输出到「日」；原始数据带时刻的（就诊到达时间、下单时间、消息时间）保留到分。
  • 同一条内容多处记录时输出一条、取最近一次的时间，差异在输出附注里说明。

2.3 检验记录的指标清单（按首诊问卷与体检报告圈定）

血压、空腹血糖、糖化血红蛋白（HbA1c）、总胆固醇、甘油三酯、低密度脂蛋白胆固醇（LDL-C）、高密度脂蛋白胆固醇（HDL-C）、尿酸、丙氨酸转氨酶（ALT）、天冬氨酸转氨酶（AST）、空腹胰岛素。

  • 以上是按首诊问卷涉及的健康史、指标、用药题目与体检报告「主要发现」圈定的相关化验指标；清单外有数据也输出，清单内没有就不输出、不造数。
  • 体检报告「主要发现」里的结论性描述（如脂肪肝）属影像 / 检查结论，进检查记录域，不进检验记录。

3. 同一件事多处记录时，用哪一份

总原则（来源可信度优先级）：

院内病历 = 院内体检 = 院内检查 ＞ 院外病历 = 院外体检 = 院外检查 ＞ 问卷 ＞ 小程序记录

  • 同一个指标多处都有时，以优先级最高的来源为准；同级有多条的，取时间最新的一条。
  • 优先级低的记录不丢弃，仍保留在各明细里（体重趋势、新鲜度要用）。

几条具体口径：

  • 体重：全部记录照常进明细；对外展示的「当前体重」按上面的优先级取值。
  • 身高：只认体检（院内 / 院外体检）里的；就诊记录和问卷自填的不用。
  • 性别、年龄：性别用就诊人表，年龄按出生日期现算；问卷里填的只做对账。
  • BMI：不照抄报告，用「最新实测体重 ÷ 身高²」现算，保留 1 位小数。
  • 疾病、用药：不做归类清洗，病历原文进数据集，归类由消费方（AI 总结）处理。
  • 异常判断：检验记录、检查记录里 abnormal = 是 的就是异常项；「未见异常」类描述不输出。

4. 这些字段不要（用不到的都删掉）

删掉的 原因
问卷填写渠道、问卷初筛结果、问卷记录编号 工程字段
问卷第①②③题的答案 和档案重复，只做对账
体检报告「体检建议」原文 是建议不是事实，异常情况已由检验记录承载
各表的创建时间、更新时间、逻辑删除等工程字段 工程字段

5. 体重新鲜度

  • 最近一次实测体重距今 超过 3 个月 → 标「过期，需重填」；
  • 距今 2~3 个月 → 标「临界，建议复测」；
  • 3 个月以内 → 标「新鲜」；
  • 没有任何实测体重（只有问卷自填）→ 标「无实测数据，需实测」。

6. 特殊情况处理

情况 处理
病在问卷选项里找不到（如肾病综合征） 病历与问卷第⑧题原文照常进数据集，不强行归到问卷选项
患者在「指标偏高」题勾了其实已经确诊的项目 属于常见误选，保留原样，不擅自清洗掉
男性跳过「备孕怀孕哺乳」题 孕产阶段记「未作答」，不算缺失
某次就诊只测了体重、医生没写病历 就诊记录照常输出（病历内容为空），该次体重照常进基础指标，不报错
体检报告太旧（如 2 年前、当时体重还正常） 报告已过有效期：其检验记录条目标「过期」，不当现状展示；基础指标里的历史测量值照常保留

7. 数据红线

  • 病历原文、检验原值、企业微信聊天记录内容 只在医生端数据集与医生端页面出现，用户端一律不展示；
  • 输出数据里不得出现姓名之外的身份信息（手机号、身份证、地址等）；
  • 体检报告「体检建议」等建议类文本不进入数据集。
