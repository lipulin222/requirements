## 1. 背景与目标

**问题**：减重卡在服务周期内会经历多个阶段，不同阶段应展示不同内容；目前卡片内容写死，且服务中用户可能看到与真实进度不符的内容。

**目标**：**阶段由服务端计算**，前端按阶段渲染核心区模块与 CTA；数据缺失时按规则降级，不编造、不留白。

> 本单只管**单张卡内部**的渲染；「是否服务中」由 `STATUS-01` 判定，「卡与卡之间的顺序」由 `STATUS-02` 定义。

---

## 2. 规则

### 2.1 阶段定义与流转

| 阶段 | 进入条件 | 状态标签 |
| --- | --- | --- |
| 未开始 | 无有效处方或支付（`STATUS-01` 判定不成立） | 未开始（灰） |
| **进行中** | `STATUS-01` 判定成立 | 进行中（teal） |
| 维持期 | 服务期结束（按剂量周期，见 `STATUS-01`） | 维持期（绿） |
| 已结束 | 维持期满 2 个月 | 已结束（灰） |

- 流转**单向**：未开始 → 进行中 → 维持期 → 已结束。
- **例外**：退款 / 处方作废 → 回退到「未开始」。
- 续费不重置阶段，只更新月序与剂量（见 `STATUS-01`）。

### 2.2 各阶段核心区内容

| 阶段 | 核心区模块 |
| --- | --- |
| 未开始 | 科普入口 + 用药适应性评估入口 + AI 助理 |
| 进行中 | 方案名 + 当前月序/剂量 + 体重变化（有数据才显示）+ 知识库入口 + 主 CTA |
| 维持期 | 成果数据（体重/腰围变化）+ 维持建议 + 复查入口 |
| 已结束 | 回顾入口 + 再次购买入口（不置顶） |

### 2.3 CTA 规则

- **一卡一行动**：每阶段至多 **1 个主 CTA**，其余为次行动。
- CTA 由服务端下发，前端不写死文案与目标。

| 阶段 | 建议主 CTA |
| --- | --- |
| 未开始 | 用药适应性评估 |
| 进行中 | AI 减重助理 / 记录数据（按阶段进度由服务端给） |
| 维持期 | 复查预约 |
| 已结束 | 再次购买 |

### 2.4 数据缺失降级

- 月序/剂量能算则显示，**算不出就隐藏该模块**，不显示占位数字。
- 体重变化**无数据则隐藏**，**不得编造**、不留白块。
- 接口失败 → 保留卡片骨架 + 重试入口，**卡片不消失**，页面其余部分正常。

### 2.5 禁止项

- 不向用户展示**阶段编号、进度条**等内部信息。
- 判定成立时**不得显示「未开始」**。
- 不出现红点、倒计时、限时等施压元素。
- 不承诺具体减重斤数。

## 3. 字段与接口

### 接口

`GET /weight/card`

| 项 | 内容 |
| --- | --- |
| 请求参数 | `user_id`、`platform` |
| 响应 | `stage`、`plan_id`、`month_index`、`dose_mg`、`weight_delta`、`kb_items[]`、`ctas[]`、`pinned` |
| 异常码 | `401/403` → 跳登录；`404` 无卡片 → 不渲染；`500/timeout` → 骨架 + 重试 |
| 降级 | 接口失败保留骨架与重试，不隐藏卡片 |

### 字段

| 字段 | 说明 |
| --- | --- |
| `stage` | `未开始 / 进行中 / 维持期 / 已结束` |
| `plan_id` | 方案标识 |
| `month_index` | 当前月序（按剂量爬坡推算，见 `STATUS-01`） |
| `dose_mg` | 当前剂量（mg/周） |
| `weight_delta` | 体重变化（无数据为 `null`） |
| `kb_items[]` | 知识库入口条目（文章 id + 标题） |
| `ctas[]` | 行动按钮（`id`、`text`、`target`、`is_primary`） |
| `pinned` | 是否置顶（由 `STATUS-02` 消费） |

## 4. 验收与上线要求

**验收清单**

- [ ] 阶段由服务端返回，前端无阶段判断逻辑
- [ ] 四个阶段的核心区模块按 2.2 渲染，CTA 按 2.3 且只有一个主行动
- [ ] 判定成立时不出现「未开始」
- [ ] 月序/剂量缺失时隐藏该模块，不显示占位数字
- [ ] 体重无数据时隐藏，不编造
- [ ] 接口失败保留骨架 + 重试，卡片不消失
- [ ] 退款/作废后阶段回退到「未开始」
- [ ] 续费不重置阶段，只更新月序与剂量
- [ ] UI 无阶段编号、进度条、红点、倒计时
- [ ] 小程序与 H5 两端渲染一致

**上线要求（本单特有）**

1. 阶段与核心区内容**全部服务端下发**，前端不内置阶段文案与模板。
2. 卡片数据与首屏数据合并下发，避免二次请求导致跳动。
3. 知识库条目 id 必须能被科普页正确打开（无死链）。
4. 内容文案需医学/合规审核留痕。

## 5. 依赖与风险

| 项 | 说明 | 应对 |
| --- | --- | --- |
| 依赖 `STATUS-01` | 阶段进入条件由判定结果驱动 | 本单只消费 `stage` |
| 依赖 `STATUS-02` | 是否置顶由该单定义 | 本单下发 `pinned` 供其消费 |
| 依赖 `EDU-01` | 知识库条目跳转科普页 | 文章 id 需稳定，上线前校验无死链 |
| 依赖 `AI-01` | CTA 跳转 AI 助理 | 需带上下文，避免重复采集 |
| 阶段计算错误 | 阶段算错会导致整张卡内容错 | 服务端可观测 + 可人工修正 |
| 内容合规 | 卡片文案涉医疗表述 | 需审核留痕，禁止疗效承诺 |
