# 提炼字段清洗（AI 诊断数据集）

> 编号 `REQ-WL-DATA-01` ｜ 项目：科学减重（WL）｜ 模块：数据清洗 ｜ 状态：制定中
> 一句话：把 6 张业务表合并成「每人一份、17 个字段」的提炼数据集，供减重问卷分流判定和医生端「患者身体状况 AI 总结」使用。效果可看 [医生速览页](https://lipulin222.github.io/health-subscription-demo/patient-ai-summary/)。

---

## 1. 做什么

系统里关于一个患者的信息分散在 6 张表里，很多内容重复记录、有的是自由文本，不能直接用来做分流判定。本需求要求把这 6 张表洗成 **每个就诊人一份、固定 17 个字段** 的数据集。

**输入表（6 张）**

| 表 | 关键内容 |
| --- | --- |
| 就诊人基本信息 | 姓名、性别、出生日期 |
| 订单 | 订单号、商品名、类别、规格、创建时间 |
| 就诊记录 | 到达时间、身高、体重、病历内容（医生写的自由文本） |
| 体检报告 | 身高体重 BMI、血压、脉搏、腰围、家族史、既往病史、主要发现、体检建议、创建时间 |
| 问卷记录 | 提交时间、填写渠道、初筛结果 |
| 问卷答案 | 10 道题的逐题回答 |

**输出的 17 个字段（7 组）**

| 组 | 字段 |
| --- | --- |
| A 基础身份（4） | 就诊人 ID、姓名、性别、出生日期 |
| B 体重记录（1） | **全部体重记录明细**：每条含体重数值、记录时间、记录来源（就诊记录 / 体检报告 / 问卷自填），按时间排序输出；并对最近一次实测标注新鲜度（规则见 5.1） |
| C 疾病与用药（4） | 确诊疾病清单、当前用药类别、家族史、其他重要病史 |
| D 关键指标（3） | 血压（标注是否服药中）、异常指标清单、腰围 |
| E 安全筛查（2） | 禁忌症（是 / 否 / 不确定）、孕产状态（备孕 / 怀孕 / 哺乳 / 否，男性跳过） |
| F 归因与意愿（2） | 体重增加自评原因、减重目标 |
| G 系统判定（1） | 预期分流档位（无慢病 / 轻微异常 / 线下优先 / 排除）+ 触发依据 |

---

## 2. 输出数据表结构设计

输出为**每就诊人一条主记录 + 一张体重明细子表**（JSON 或关系表均可，字段与类型如下，开发照此建表 / 定接口）。

### 2.1 主表字段字典（17 字段）

| # | 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | patient_id | 文本 | 必填 | 就诊人 ID，来自就诊人基本信息表 |
| 2 | name | 文本 | 必填 | 姓名 |
| 3 | gender | 枚举：M / F | 必填 | 只取就诊人表（第 3 节） |
| 4 | birth_date | 日期 | 必填 | 出生日期，年龄由它现算 |
| 5 | weight_data | 对象（见 2.2） | 必填（records 可为空数组） | 全部体重明细 + 新鲜度 |
| 6 | diagnosed_diseases | 对象数组 `{item, recorded_at}` | 必填（可为空） | 确诊疾病清单，统一命名后去重；每条带该条记录的时间戳 |
| 7 | medication_categories | 对象数组 `{category, recorded_at}` | 必填 | `胰岛素 / 口服降糖药 / 降压药 / 他汀或抗凝 / 糖皮质激素 / 其他处方药 / 无`，多选；每类带发现该药的病历 / 订单时间 |
| 8 | family_history | 对象数组 `{item, recorded_at}` | 必填（可为空） | 家族史，合并去重，每条带时间戳 |
| 9 | other_history | 对象数组 `{item, recorded_at}` | 必填（可为空） | 其他重要病史，每条带时间戳 |
| 10 | blood_pressure | 对象 | 必填（可为空） | `{systolic:int, diastolic:int, on_medication:bool, recorded_at}`，缺测整体置空 |
| 11 | abnormal_indicators | 对象数组 `{item, recorded_at}` | 必填（可为空） | 异常指标清单（只收「偏高 / 异常」项），每条带报告时间 |
| 12 | waist_cm | 对象 `{value_cm, recorded_at}` | 否 | 腰围值 + 测量时间，缺失输出「缺失」 |
| 13 | contraindication | 对象 `{value, recorded_at}` | 必填 | 禁忌症（枚举：有 / 无 / 不确定），带问卷提交时间 |
| 14 | pregnancy_status | 对象 `{value, recorded_at}` | 必填 | 枚举：备孕 / 怀孕 / 哺乳 / 无 / 未作答（男性记「未作答」），带问卷提交时间 |
| 15 | weight_gain_causes | 对象数组 `{item, recorded_at}` | 必填 | 体重增加自评原因（多选），带问卷提交时间 |
| 16 | weight_goal | 对象 `{text, recorded_at}` | 必填 | 减重目标，带问卷提交时间 |
| 17 | expected_tier | 枚举：无慢病 / 轻微异常 / 线下优先 / 排除 | 必填 | 预期分流档位，`trigger_reason`（文本）随同输出，写明触发依据与对应字段值 |

### 2.2 体重明细子表 weight_records

| 列 | 类型 | 说明 |
| --- | --- | --- |
| patient_id | 文本 | 关联主表 |
| value_kg | 数值（1 位小数） | 体重值，原样输出不换算 |
| measured_at | 日期时间 | 记录时间（无时刻的只落日期） |
| source | 枚举：`visit` 就诊记录 / `exam` 体检报告 / `questionnaire` 问卷自填 | 记录来源 |

- 明细按 `measured_at` 升序输出；同一天多条全部保留。
- 空值体重（测了但没记数值）不入明细。
- 新鲜度不落子表，按 5.1 对最近一次实测现算，输出在主表 `weight_data.freshness`。

### 2.4 时间戳约定（全字段）

**除 A 组基础身份（1~4）和 expected_tier（17）外，其余所有字段的每条内容都必须带时间戳 `recorded_at`**，口径如下：

| 数据类别 | 时间戳取值 |
| --- | --- |
| 体重明细（weight_data.records） | 该次测量的时间 |
| 就诊 / 病历 / 检查 / 身体测量类条目（疾病、用药、家族史、其他病史、血压、异常指标、腰围） | 该条业务记录的时间（就诊到达时间 / 报告创建时间） |
| 问卷类字段（禁忌症、孕产状态、自评原因、减重目标） | 问卷提交时间 |

- 同一条内容被多处记录（如疾病同时出现在病历和问卷）时，输出一条，`recorded_at` 取**最近一次**记录的时间；差异仍在触发依据里说明。
- 时间戳一律原样输出到「日」；原始数据带时刻的（如就诊到达时间）保留到分。

## 3. 同一件事多处记录时，用哪一份

| 内容 | 规则 |
| --- | --- |
| 体重 | 就诊记录、体检报告、问卷第③题都可能有。**所有来源的体重记录全部输出**（数值、记录时间、记录来源），不去重、不汇总、不取「最新一条」；问卷自填的体重照常输出，来源标「问卷」。问卷填的数和实测对不上时，把差异记进触发依据（例：问卷填 84.4kg，最近实测 83.5kg）。 |
| 身高 | **只认体检报告里的身高**。就诊记录里的身高（门诊很少复测，多为空）和问卷里自己填的都不用。 |
| BMI | 不照抄报告里的数，用「当前体重 ÷ 身高²」现算，保留 1 位小数。 |
| 年龄 | 用出生日期算。问卷里自己填的年龄只用来对账，对不上要在输出里提示。 |
| 性别 | 只用就诊人表里的，问卷第①题只做对账。 |
| 确诊疾病 | 体检报告「既往病史」+ 问卷第⑤题 + 病历里写到的诊断，三处合并去重。同一种病的不同叫法要统一成一种说法（以病历写法为准）。 |
| 当前用药 | 从病历文本和订单商品名里找药，归类成：胰岛素 / 口服降糖药 / 降压药 / 他汀或抗凝 / 糖皮质激素 / 其他处方药 / 无。用药类别直接决定分流档位，**宁可多归不可漏归**。 |
| 家族史 | 体检报告「家族史」+ 问卷第④题勾选的「遗传 / 家族因素」，合并去重。 |
| 异常指标 | 从体检报告「主要发现」里只抽「偏高 / 异常」的结论项（血脂、血糖或糖化、尿酸、肝功、脂肪肝、胰岛素等），再和问卷第⑥题合并去重。「未见异常」之类的描述全部丢掉。 |
| 各种时间 | 就诊、报告、问卷、订单的时间都不单独输出，只用来算下面第 5 节的「新鲜度」。 |

## 4. 这些字段不要（用不到的都删掉）

| 删掉的 | 原因 |
| --- | --- |
| 脉搏 | 不参与任何分流规则 |
| 订单号、商品类别、规格、商品名原文 | 对判定没用；订单只保留两个「是 / 否」标记：是否购买过减重服务、是否购买过慢病处方药 |
| 问卷填写渠道、问卷初筛结果、问卷记录编号 | 工程字段 |
| 问卷第①②③题的答案 | 和档案重复，只做对账 |
| 体检报告「体检建议」原文 | 和异常指标重叠，且是建议不是事实 |
| 各表的创建时间、更新时间、逻辑删除等工程字段 | 工程字段 |

---

## 5. 两个判定规则

**5.1 体重新鲜度**

- 最近一次实测体重距今 **超过 3 个月** → 标「过期，需重填」；
- 距今 **2~3 个月** → 标「临界，建议复测」；
- 3 个月以内 → 标「新鲜」。

**5.2 反弹次数（溜溜球判定）**

- 把近 24 个月内的就诊体重按时间排序；
- 体重比上一次 **下降 2kg 及以上**，之后又 **回升 2kg 及以上**，记反弹 1 次；
- 反弹 **2 次及以上** 即判定为「溜溜球体重」；
- 反弹次数**不再作为独立字段输出**，由体重明细现算，命中「线下优先（溜溜球）」时把反弹次数写进触发依据（如「体重明细显示反弹 3 次」）。

## 6. 分流档位怎么定

按下面的顺序判断，**排在前面的先看，命中就定档**：

1. **先看排除**：年龄不满 18 岁、孕产状态是备孕 / 怀孕 / 哺乳、禁忌症答「有」——只要占一条，直接判「排除」（排除优先级最高，其他条件再符合也排除）；
2. **再看需要医生把关的情形**：确诊糖尿病（尤其正在打胰岛素）、确诊冠心病或中风、正在用糖皮质激素（可能是药物引起的增重）、严重肾脏疾病——判「线下优先」；
3. **再看体重反复**：没有确诊疾病，但反弹 2 次及以上——判「线下优先（溜溜球）」；
4. **再看指标偏高**：没有确诊疾病，但异常指标清单不为空——判「轻微异常」，输出里带「建议复查××」；
5. **最后看是否符合适应症**：BMI ≥ 28，或 BMI ≥ 24 且有体重相关合并症——判「无慢病，直达订阅」。

每条分档结论都必须写清「触发依据」，指到具体字段值（如「确诊 2 型糖尿病 + 当前用药含胰岛素」），不允许只给档位不给原因。

## 7. 特殊情况处理

| 情况 | 处理 |
| --- | --- |
| 病在问卷选项里找不到（如肾病综合征） | 以病历和问卷第⑧题「其他病史」为准定档，并在触发依据里标注「问卷选项未覆盖」。只看问卷第⑤题会漏判 |
| 患者在「指标偏高」题勾了其实已经确诊的项目 | 属于常见误选，**保留原样**并在触发依据里说明，不要擅自清洗掉 |
| 男性跳过「备孕怀孕哺乳」题 | 该字段记「未作答」，不算缺失 |
| 某次就诊只测了体重、医生没写病历 | 病历为空不报错，该次体重照常进体重明细 |
| 体检报告太旧（如 2 年前、当时体重还正常） | 报告已过有效期时，异常指标、腰围等一律标「无有效数据」，不得拿旧报告当现状 |

---

## 8. 数据红线

- 血压、血糖、血脂等指标原值 **只在医生端展示**，用户端不展示原值；
- 输出数据里不得出现姓名之外的身份信息（手机号、身份证、地址等）；
- 病历原文、报告原文不直接输出，一律按第 2 节归类成结构化字段。
