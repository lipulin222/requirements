# 提炼字段清洗（AI 诊断数据集）

> 编号 `REQ-WL-DATA-01` ｜ 项目：科学减重（WL）｜ 模块：数据清洗 ｜ 状态：制定中
> 一句话：把 6 张业务表和企业微信沟通记录合并成「每人一份、按 10 个数据域组织」的提炼数据集（所有明细带时间戳与来源），供减重问卷分流判定和医生端「患者身体状况 AI 总结」使用。效果可看 [医生速览页](https://lipulin222.github.io/health-subscription-demo/patient-ai-summary/)。

---

## 1. 做什么

系统里关于一个患者的信息分散在 6 张业务表和企业微信沟通记录里，很多内容重复记录、有的是自由文本，不能直接拿来用。本需求要求把这些数据洗成 **每个就诊人一份、按 10 个数据域组织** 的数据集。

**输入数据（6 张表 + 企微记录）**

| 表 | 关键内容 |
| --- | --- |
| 就诊人基本信息 | 姓名、性别、出生日期 |
| 订单 | 订单号、商品名、类别、规格、创建时间 |
| 就诊记录 | 到达时间、接诊医生、身高、体重、病历内容（医生写的自由文本） |
| 体检报告 | 身高体重 BMI、血压、脉搏、腰围、家族史、既往病史、主要发现、体检建议、创建时间 |
| 问卷记录 | 提交时间、填写渠道、初筛结果 |
| 问卷答案 | 10 道题的逐题回答 |
| 企业微信沟通记录 | 患者与顾问 / 医生的聊天内容、消息时间（感受反馈与副作用线索的来源） |

**输出的 10 个数据域**

| 数据域 | 内容 |
| --- | --- |
| 基础信息 | 就诊人 ID、姓名、性别、年龄（现算）、出生日期 |
| 消费记录 | 订单编号、下单时间、商品内容（商品名）、类别、规格 |
| 就诊记录 | 就诊时间、接诊医生、病历内容原文 |
| 用药信息 | 药品名称、剂量（从病历与订单商品里提取，每条带来源） |
| 副作用情况 | 用药过程中出现的不适 / 副作用描述（从病历与企业微信聊天记录提取，每条带时间与来源） |
| 基础指标 | 身高、体重、心率、腰围的**全部测量明细**（数值 + 测量时间 + 来源），体重另带新鲜度 |
| 检验记录 | 血压、血糖、血脂等检验 / 体检发现（数值或描述 + 参考范围 + 是否异常 + 检验时间 + 来源），指标清单见 2.3 |
| 安全筛查 | 禁忌症（有 / 无 / 不确定 + 命中项）、孕产阶段、年龄准入（是否满 18） |
| 心态相关 | 减重目标、原因自评、治疗目标（除体重数字外的目标）、感受反馈（从企业微信聊天记录提取） |
| 分流标签 | 预期分流档位（无慢病 / 轻微异常 / 线下优先 / 排除）+ 触发依据 |

---

## 2. 输出数据表结构设计

输出为**每就诊人一条主记录**，主记录下按数据域组织（JSON 或关系表均可，开发照此建表 / 定接口）。所有明细条目带时间戳 `recorded_at` 和来源 `source`（约定见 2.4）。

### 2.1 各数据域字段定义

**基础信息 patient_info（单对象）**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| patient_id | 文本 | 必填 | 就诊人 ID，主键，来自就诊人基本信息表 |
| name | 文本 | 必填 | 姓名 |
| gender | 枚举：M / F | 必填 | 只取就诊人表（第 3 节） |
| birth_date | 日期 | 必填 | 出生日期 |
| age | 整数 | 必填 | 按出生日期现算；问卷自填年龄只做对账，对不上在分流标签里提示 |

**消费记录 orders（数组）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | 文本 | 订单号 |
| recorded_at | 日期时间 | 下单时间 |
| product_name | 文本 | 商品内容（商品名原文） |
| category | 文本 | 类别 |
| spec | 文本 | 规格 |
| treatment_duration | 文本 | 药程：患者使用减重药物的持续时间（如「24 周」），来自订单 / DMS 处方信息 |

**就诊记录 visits（数组）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| recorded_at | 日期时间 | 就诊到达时间 |
| doctor_name | 文本 | 接诊医生 |
| source | 枚举：线上 / 线下 | 就诊来源 |
| record_text | 文本 | 病历内容原文（仅医生端可见，见第 8 节红线） |

**用药信息 medications（数组）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| drug_name | 文本 | 药品名称（从病历文本与订单商品名提取） |
| dosage | 文本 | 剂量 / 用法，写不出的标「未记录」 |
| recorded_at | 日期时间 | 提取依据那条病历 / 订单的时间 |
| source | 枚举：`visit` 病历 / `order` 订单 | 来源 |

**副作用情况 side_effects（数组）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| item | 文本 | 副作用 / 不适描述（如「恶心，饭后明显」「注射部位红肿」） |
| recorded_at | 日期时间 | 病历记录时间或企微消息时间 |
| source | 枚举：`visit` 病历 / `wecom` 企业微信聊天记录 | 来源 |

- 从病历文本和企业微信聊天记录中提取患者描述的不适与副作用；提到具体药物的一并注明（写在 item 里，如「注射替尔泊肽后恶心」）。
- 顾问 / 医生回复的安抚内容不算副作用，不提取；同一不适多次反馈逐条保留，不合并。

**基础指标 body_metrics（数组）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| metric | 枚举：`身高` / `体重` / `心率` / `腰围` | 指标名 |
| value | 数值（1 位小数） | 测量值，原样输出不换算 |
| unit | 枚举：cm / kg / 次 / 分 | 单位 |
| recorded_at | 日期时间 | 测量时间（无时刻的只落日期） |
| source | 枚举：`visit` 就诊记录 / `exam` 体检报告 / `questionnaire` 问卷自填 | 来源 |

- 同一指标多条全部保留，按时间升序；同一天多条不合并。
- 空值测量（测了没记数值）不入明细。
- 体重明细单独支撑：新鲜度（5.1）与反弹判定（5.2）。

**检验记录 lab_results（数组）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| item | 文本 | 指标名（清单见 2.3，清单外有数据也输出） |
| value | 文本 / 数值 | 数值或描述（如「轻度脂肪肝」） |
| unit | 文本 | 单位，描述类为空 |
| reference_range | 文本 | 参考范围，报告有就带 |
| abnormal | 枚举：是 / 否 | 是否偏高 / 异常；「未见异常」类描述不输出 |
| recorded_at | 日期 | 检验 / 报告时间 |
| source | 枚举：`院内检查` / `院内体检` / `院外体检` / `小程序记录` / `用户自述` / `其他` | 数据来源 |

**安全筛查 safety_screening（单对象）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| contraindication | 枚举：有 / 无 / 不确定 | 禁忌症（问卷） |
| contraindication_items | 文本数组 | 答「有」时的具体命中项 |
| pregnancy_status | 枚举：备孕 / 怀孕 / 哺乳 / 无 / 未作答 | 孕产阶段；男性记「未作答」 |
| age_ok | 布尔 | 是否满 18 周岁（按出生日期现算） |
| recorded_at | 日期时间 | 数据录入时间（不等于问卷提交时间：后台补录、修改后以最近一次录入时间为准） |

**心态相关 psychology（单对象）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| weight_goal | 文本 | 减重目标 |
| gain_causes | 文本数组 | 体重增加原因自评（多选原文） |
| treatment_goals | 文本数组 | 除体重数字外的治疗目标（问卷第⑩题） |
| feedback | 对象数组 `{text, recorded_at}` | 感受反馈：从企业微信聊天记录里提取的患者主观感受（如「这周不容易饿了」「晚上睡得好了」），每条带消息时间；顾问回复不提取 |
| recorded_at | 日期时间 | 问卷提交时间（feedback 的各条时间在条目内） |

**分流标签 triage（单对象）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| expected_tier | 枚举：无慢病 / 轻微异常 / 线下优先 / 排除 | 预期分流档位（规则见第 6 节） |
| trigger_reason | 文本 | 触发依据，指到具体字段值（如「就诊记录提及 2 型糖尿病 + 用药信息含胰岛素」），不允许只给档位不给原因 |

### 2.2 时间戳约定（全字段）

**除基础信息（patient_info）和分流标签（triage）外，其余每个数据域的每条明细都必须带时间戳 `recorded_at` 与来源 `source`**：

| 数据类别 | 时间戳取值 |
| --- | --- |
| 消费记录 | 订单下单时间 |
| 就诊记录 | 就诊到达时间 |
| 用药信息 | 提取依据那条病历 / 订单的时间 |
| 副作用情况 | 病历记录时间或企微消息时间（按来源） |
| 基础指标 | 该次测量时间 |
| 检验记录 | 检验 / 报告时间 |
| 安全筛查 | 数据录入时间 |
| 心态相关 | 问卷字段用问卷提交时间；感受反馈各条用企微消息时间 |

- 时间戳原样输出到「日」；原始数据带时刻的（就诊到达时间、下单时间）保留到分。
- 同一条内容多处记录时输出一条、取最近一次的时间，差异在分流标签触发依据里说明。

### 2.3 检验记录的指标清单（按首诊问卷与体检报告圈定）

血压、空腹血糖、糖化血红蛋白（HbA1c）、总胆固醇、甘油三酯、低密度脂蛋白胆固醇（LDL-C）、高密度脂蛋白胆固醇（HDL-C）、尿酸、丙氨酸转氨酶（ALT）、天冬氨酸转氨酶（AST）、空腹胰岛素、肝脏超声（脂肪肝）。

- 以上是按首诊问卷涉及的健康史、指标、用药题目与体检报告「主要发现」圈定的相关指标；**清单外有数据也输出**，清单内没有就不输出、不造数。
- 体检报告「主要发现」里的结论性描述（如脂肪肝）作为条目输出，`abnormal` 按报告标「是」。

## 3. 同一件事多处记录时，用哪一份

| 内容 | 规则 |
| --- | --- |
| 体重 | 就诊记录、体检报告、问卷第③题都可能有。**所有来源的体重记录全部输出**（数值、测量时间、来源），不去重、不汇总、不取「最新一条」；问卷自填的体重照常输出，来源标「问卷」。问卷填的数和实测对不上时，把差异记进分流标签触发依据（例：问卷填 84.4kg，最近实测 83.5kg）。 |
| 身高 | **只认体检报告里的身高**。就诊记录里的身高（门诊很少复测，多为空）和问卷里自己填的都不用。 |
| BMI | 不照抄报告里的数，用「最新实测体重 ÷ 身高²」现算，保留 1 位小数，写在分流标签触发依据里。 |
| 年龄 | 用出生日期算。问卷里自己填的年龄只用来对账，对不上要在分流标签里提示。 |
| 性别 | 只用就诊人表里的，问卷第①题只做对账。 |
| 疾病 | 体检报告「既往病史」+ 问卷第⑤题 + 病历里写到的诊断，三处合并去重；同一种病的不同叫法统一成一种说法（以病历写法为准）。**不单独设疾病清单字段**，归类结果直接写进分流标签触发依据。 |
| 用药 | 药品名称、剂量逐条进用药信息；分流所需的类别归类（胰岛素 / 口服降糖药 / 降压药 / 他汀或抗凝 / 糖皮质激素 / 其他处方药 / 无）**宁可多归不可漏归**，写在触发依据里。 |
| 家族史 | 不单独输出（分流规则用不到）；原文保留在体检报告与病历内容里，医生端可查。 |
| 异常指标 | 检验记录里 `abnormal = 是` 的条目；「未见异常」之类的描述全部丢掉。 |
| 各种时间 | 除按 2.2 作为各条明细的时间戳外，不再单独输出时间字段。 |

## 4. 这些字段不要（用不到的都删掉）

| 删掉的 | 原因 |
| --- | --- |
| 问卷填写渠道、问卷初筛结果、问卷记录编号 | 工程字段 |
| 问卷第①②③题的答案 | 和档案重复，只做对账 |
| 体检报告「体检建议」原文 | 是建议不是事实，异常情况已由检验记录承载 |
| 各表的创建时间、更新时间、逻辑删除等工程字段 | 工程字段 |

---

## 5. 体重新鲜度

- 最近一次实测体重距今 **超过 3 个月** → 标「过期，需重填」；
- 距今 **2~3 个月** → 标「临界，建议复测」；
- 3 个月以内 → 标「新鲜」；
- 没有任何实测体重（只有问卷自填）→ 标「无实测数据，需实测」。

---

## 6. 分流档位怎么定

按下面的顺序判断，**排在前面的先看，命中就定档**：

1. **先看排除**：年龄不满 18 岁（`age_ok = false`）、孕产阶段是备孕 / 怀孕 / 哺乳、禁忌症答「有」——只要占一条，直接判「排除」（排除优先级最高，其他条件再符合也排除）；
2. **再看需要医生把关的情形**：确诊糖尿病（尤其正在打胰岛素）、确诊冠心病或中风、正在用糖皮质激素（可能是药物引起的增重）、严重肾脏疾病——判「线下优先」；
3. **再看指标偏高**：没有确诊疾病，但检验记录里 `abnormal = 是` 的条目（在有效期内）不为空——判「轻微异常」，触发依据带「建议复查××」；
4. **最后看是否符合适应症**：BMI ≥ 28，或 BMI ≥ 24 且有体重相关合并症——判「无慢病，直达订阅」。

体检报告已过有效期时，其检验条目不得作为第 4 条的判定现状（见第 7 节）。

## 7. 特殊情况处理

| 情况 | 处理 |
| --- | --- |
| 病在问卷选项里找不到（如肾病综合征） | 以病历和问卷第⑧题「其他病史」为准定档，并在触发依据里标注「问卷选项未覆盖」。只看问卷第⑤题会漏判 |
| 患者在「指标偏高」题勾了其实已经确诊的项目 | 属于常见误选，**保留原样**并在触发依据里说明，不要擅自清洗掉 |
| 男性跳过「备孕怀孕哺乳」题 | 孕产阶段记「未作答」，不算缺失 |
| 某次就诊只测了体重、医生没写病历 | 就诊记录照常输出（病历内容为空），该次体重照常进基础指标，不报错 |
| 体检报告太旧（如 2 年前、当时体重还正常） | 报告已过有效期：其检验记录条目标「过期」，不得当现状参与分流；基础指标里的历史测量值照常保留（体重明细、反弹判定要用） |

## 8. 数据红线

- 病历原文、检验原值、企业微信聊天记录内容 **只在医生端数据集与医生端页面**出现，用户端一律不展示；
- 输出数据里不得出现姓名之外的身份信息（手机号、身份证、地址等）；
- 体检报告「体检建议」等建议类文本不进入数据集。
