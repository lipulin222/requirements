# 减重评估报告：页面结构与正文接口

> 编号 `REQ-WL-PLAN-03` ｜ 项目：科学减重（WL）｜ 模块：方案·评估·随访 ｜ 优先级 P0 ｜ 状态：待评审
> Demo：[评估报告](https://lipulin222.github.io/online-health-care/weight-companion-ui/weight-management/Assessment-report/index.html) ｜ 埋点：`REQ-WL-BASE-01`

---

## 1. 本单管什么

- 本单只负责评估报告页面的**展示、结构和逻辑**：模块构成、出现与排序规则、排版、正文内容的获取方式。
- **正文文案待定**：各分支具体话术由产品 / 医疗后续打磨后另行回填，本单不展开。

## 2. 页面结构（自上而下）

1. 结论头：档案行 + 三档刻度 + 一句话总结（分支判定与结论头规则见 `REQ-WL-PLAN-02`）。
2. 正文模块，共 4 个：`饮食建议` / `运动建议` / `慢病管理建议` / `用药建议`，编号按实际渲染顺序重排。各分支的模块构成与顺序：

| 分支 | 模块顺序 |
| --- | --- |
| chronic | 慢病管理建议 → 饮食建议 → 运动建议 → 用药建议 |
| mild / normal | 饮食建议 → 运动建议 → 用药建议 |
| adapt | 饮食建议 → 运动建议 → 用药建议（只讲为什么不用药） |

3. 页脚固定声明：`本页内容基于你填写的问卷与已关联的健康数据生成，为初步评估建议，不构成诊断和处方。`

## 3. 正文内容的接口与调用逻辑（@冠成 @张林 对齐）

- 四个模块的正文文案由**服务端下发**，前端不写死；后续文案打磨只改服务端内容，页面无需发版。
- 请求逻辑：
  1. 进入页面时，携带用户 / 问卷结果标识（分支结果与问卷勾选），请求一次正文内容；
  2. 服务端按分支返回各模块的标题、编号、正文段落与展示顺序；
  3. 加载中显示骨架占位；请求失败显示错误态并提供重试，不白屏。
- 接口契约（路径、入参、出参字段、错误码）由后端 @冠成 与前端 @张林 对齐定稿后回填本节。

## 4. 排版

模块内相邻块 10px，行高 21px；正文里的病名 / 指标用用户问卷勾选原文替换。

## 5. 验收

- [ ] 四分支 × 模块矩阵与第 2 节一致，无缺无多
- [ ] 正文文案全部来自接口，前端无写死文案
- [ ] 接口失败显示错误态并可重试，不白屏
- [ ] 正文里的病名 / 指标与问卷勾选原文一致
- [ ] 接口契约已在 @冠成 @张林 之间对齐并回填第 3 节
