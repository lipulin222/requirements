1. 交付定位

可上线面向用户使用的产品能力，不是演示原型。 载体：App + 微信小程序。

2. 通用基线（每单默认适用）

类别 要求
载体 App 与小程序业务逻辑一致，差异只在壳层 API
接口 业务数据全部来自服务端，前端不硬编码
登录态 小程序静默授权（openid/unionid）+ 手机号授权（敏感操作前）；App 走自身登录态；token 无感续期
异常兜底 每个请求具备 loading / 空态 / 失败重试 / 超时兜底；弱网、离线有明确提示与恢复入口
性能 4G 中端机首屏 ≤1.5s、可交互 ≤2.5s；图片 CDN + 懒加载；长列表分页；小程序分包
兼容 iOS 14+ / Android 8+；微信 8.0+；小程序基础库 ≥2.30；刘海屏与底部安全区适配
安全 全链路 HTTPS；接口签名 + 防重放；敏感数据脱敏；前端不落地任何密钥
隐私合规 隐私政策 + 用户协议；未授权不采集设备信息；健康数据不落 URL / 不落本地明文；未成年人需监护人授权
灰度回滚 按版本/用户灰度，可一键回滚；发布前后核心指标对比
监控告警 接口成功率、前端错误、埋点上报成功率接入告警

3. 上线放行清单（每单上线前逐条确认）

  • 业务数据全部来自接口，代码中无业务硬编码与占位符
  • App 与小程序两端表现一致，真机回归通过
  • 空态 / 加载态 / 失败态 / 弱网态均有设计并验证
  • 无 toast 占位入口；未上线能力一律不渲染
  • 性能达标，首屏无布局跳动
  • 埋点按 REQ-WL-BASE-01 接入，上报成功率 ≥99%
  • 隐私合规检查通过；健康数据无明文落盘/落 URL
  • 灰度与回滚方案就绪

4. 小程序适配要点

  1. web-view 内嵌页面：需配置业务域名白名单；支付、授权、订阅消息不能直接调用，需 wx.miniProgram 桥接。
  2. 原生页面：支付用 wx.requestPayment，提醒用订阅消息。
  3. 两端跳转路径不同（App 路由 / 小程序绝对路径白名单），BASE 必须环境化，禁止硬编码域名。
  4. 分享：小程序用 onShareAppMessage + canvas 生成海报；分享内容必须脱敏。
